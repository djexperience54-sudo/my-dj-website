# DJ Website - Design Brief

## Status

APPROVED - INITIAL IMPLEMENTATION

This document contains the approved initial visual and user-experience direction for the DJ website.

## Design Goals

The website should feel professional, modern, memorable, connected to the DJ and African music identity, easy to navigate, responsive, accessible and visually consistent.

## Design Decisions

### Brand Identity

* Brand name: INT'L DJ EXPERIENCE.
* Wordmark treatment with a warm gold accent.
* Personality: editorial, confident, modern and connected to African club culture.

### Colors

* White page background with near-black primary text.
* Warm gold for accents, labels and active states.
* Soft off-white surfaces and light neutral borders.
* Gold or near-black hover states with visible focus outlines.

### Typography

* Space Grotesk for display headings and the wordmark.
* DM Sans for body copy, navigation and controls.
* Large, tightly set editorial headings balanced with readable body text.

### Layout

* Constrained content width with generous vertical section spacing.
* Two-column hero on desktop and a deliberate stacked layout on mobile.
* Thin borders, restrained rounded corners and minimal card framing.
* Sticky header with primary navigation and a booking call to action.

### Homepage

The homepage is a single scrolling experience with the following order:

* Hero and primary calls to action.
* Featured mixtapes and genre navigation.
* Upcoming events.
* About preview and social links.
* Gallery preview and listening platforms.
* Booking call to action and footer.

### Responsive Design

* Desktop uses the full navigation and two-column hero.
* Mobile uses a collapsible navigation menu and stacked content layouts.
* Media grids reduce to two columns on mobile.
* Event rows simplify on smaller screens while preserving essential information.

## Future Design Areas

Mixtape details, event detail pages, gallery viewing, contact states and the admin dashboard will be designed as those milestones are built.

Future visual changes should be proposed, reviewed and documented before implementation.

The approved direction above is now the implementation target for React.
